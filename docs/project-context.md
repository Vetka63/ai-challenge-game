# Контекст для нового чата по игре

## Решения пользователя

- Работаем на Windows, родительская папка — `F:/ai-advent-challenge`.
- Игра: `ai-challenge-game`, самостоятельный Git-репозиторий.
- Ассистент: соседний `ai-challenge-code-assistants`, отдельный репозиторий.
- Оба репозитория публичные в GitHub-аккаунте `Vetka63`.
- Игра — Unity/C#, 2D, два законченных уровня, открытые ассеты с проверенными
  лицензиями. Она должна работать независимо от AI-сервисов.
- Сейчас только проектирование. Реализация начинается по отдельной команде.
- Старый `ai-chat` с заданиями прошлых недель сохраняется без изменений.

## Неутверждённые решения

Жанр, сеттинг, название, визуальный стиль, платформы, версия Unity,
render pipeline, механики и монетизация ещё не выбраны. «Два ключа» с видом
сверху, дверями и переключателями — только ранее предложенный вариант.

## Ближайший шаг

Предложить один основной концепт и две короткие альтернативы. Объяснить
игровой цикл и роль двух уровней. Задать не более трёх вопросов по текущему
шагу выбора концепции. Платформы и техническую настройку обсуждать после него.
Не создавать игровые файлы или устанавливать инструменты до согласования.

## День 31 — ассистент разработчика

Отдельный ассистент должен индексировать README и docs игры через RAG,
получать текущую Git-ветку игры через MCP и отвечать на команду `/help`
о структуре и правилах проекта. Дополнительные MCP-операции: чтение
разрешённых файлов и diff. Ветка ассистента не заменяет ветку игры.

## День 32 — автоматическое ревью

Пайплайн на PR получает diff и изменённые файлы, использует RAG по документации
и коду, возвращает потенциальные баги, архитектурные проблемы и рекомендации.
Замечания должны опираться на конкретные файлы, строки и правила.
Проверяем также корректный PR без намеренно внесённых ошибок.

Action планируется в репозитории игры, анализатор — в репозитории ассистента.
До реализации нужно согласовать версионированный способ вызова анализатора,
секреты и ограничения. Нельзя выполнять недоверенный код PR с доступом
к секретам. Unity CI-сборка и AI-ревью — разные проверки; анализ исходников
сам по себе не требует запуска Editor.

## Документация после согласования

Game design, архитектура, игровые правила, формат уровней/конфигураций,
сохранения при необходимости, тестовые сценарии и происхождение ассетов.
Правила должны соответствовать реальной игре, а не быть написаны только
для создания примеров AI-ревью.

## Связь проектов

Репозитории связаны назначением и ссылками, не общей папкой `.git` и не
копированием исходников. Ассистент будет получать разрешённый путь к игре
через локальную конфигурацию. Runtime MCP, индекс, провайдеры и CI ещё
не реализованы. Локальные пути и секреты не должны попадать в выводы ревью.
